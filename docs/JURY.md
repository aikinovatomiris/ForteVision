## Проверка с другой машины

Заполните локальный `FORTEVISION_API_KEY` в environment/.env. Используйте только собственный сервер команды. Скрипт не использует окружение proxy, не следует redirects, проверяет TLS и никогда не выводит ключ.

```powershell
python -m scripts.check_api --url https://ВАШ-ДОМЕН --video C:/allowed/video.mov --allow-remote-upload
```

Тест проверяет отказ без ключа, readiness, POST с полем file, GET polling, обязательную JSON-схему, настоящий JPEG и получение результата менее чем за 300 секунд с начала POST на стороне клиента. Отчёт `artifacts/jury_check.json` не содержит кадров или ключа.

Для нагрузки передайте несколько файлов: `--video a.mov b.mov c.mov d.mov --parallel 4`. Проверку выполнять на разрешённых development-видео; официальный test жюри не использовать для обучения/подбора параметров и не публиковать. Успешная проверка программного контракта не подтверждает точность ML.

## Текущий статус модели

Активен режим ручной проверки `action_states_v8`: кандидаты возвращаются в `review_candidates`, статус — `assessment_status=needs_review`. Они не удаляются и не считаются подтверждёнными нарушениями. `analysis_complete=false`. Для жюри, которое оценивает только бинарный `verdict` и `violations`, это **не готовый автоматический детектор**. Это остаётся блокером задания, который нельзя исправить переименованием полей.

Перед демонстрацией: `python -m scripts.preflight`; затем `python -m scripts.serve`. Результат API и кадры проверить с другой разрешённой машины. Локальный пакет подготовить `python -m scripts.export_bundle --output artifacts/fortevision-laptop.zip`; ключ передать отдельно.

## Контракт

POST `/api/v1/analyze`, multipart `file`, MOV; `X-API-Key`. Успех: HTTP 202 и только `{"job_id":"UUID"}`.

GET `/api/v1/jobs/{job_id}` с тем же ключом: processing/done/failed. При done обязательны verdict, violations, type/timecode_sec/description/evidence_frames. При no_violation список пуст. Evidence: 1–3 JPEG base64. Невалидный JPEG от ML отвергается с failed. Failed не подменяется no_violation.

Необязательные поля: `elapsed_seconds` (загрузка API + очередь + обработка), `queue_seconds`, `processing_seconds`, `within_five_minutes`; у события — `event_type` и проверенные `rule_references`. Норматив также добавляется в description, чтобы обязательные поля оставались самодостаточными. Новых обязательных полей нет.

Ошибки: 401 неверный ключ, 503 ключ не настроен/readiness не готова, 413 размер, 415 расширение, 422 содержимое/валидация, 408 слишком долгая загрузка, 429 перегрузка (`Retry-After` для полной очереди), 404 неизвестный/удалённый/истёкший результат. DELETE `/api/v1/jobs/{id}` удаляет завершённый результат, 409 если ещё выполняется.

## Время и нагрузка

295 секунд — общий серверный бюджет с начала запроса загрузки в API, включая multipart и очередь. Worker получает только оставшееся время; watchdog завершает просроченные задания, поздний результат не заменяет failed. У UI первая передача браузер → Streamlit отдельно от этого API-бюджета. Сетевые задержки клиента и прокси контролируются внешней проверкой, а не обещаются внутренним таймером.

Это ограничение времени ожидания, не гарантия успешного анализа каждого видео. Timeout/429 остаются необработанными видео по ТЗ. Проверяйте реальную нагрузку и оборудование: один worker, очередь по умолчанию 3. Не увеличивайте Uvicorn workers; для иной архитектуры нужна отдельная доработка.

## Исторический baseline (не текущий релиз)

Frontend/API, локальный inference, таймкоды и реальные evidence работают. Текущий baseline бинарный, общая категория «Признаки возможного нарушения». Пять сценариев research — кандидаты, а не распознаваемые типы. Разработчик ML должен передать валидированные типы/описания и доказательства сопоставления с правилами по [ML_INTERFACE.md](ML_INTERFACE.md).

Сохранённые baseline-метрики: 8 внутренних test-видео, precision 0.5, recall 1, F1 0.667, четыре ложные тревоги на четырёх нормальных видео. Это известное ограничение старой модели; обновлённые показатели публикуйте только после отдельной оценки. Юридическое/дисциплинарное решение принимает человек.
