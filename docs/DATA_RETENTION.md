# Данные и хранение

- Исходные дататон-видео используются только в разрешённых условиях. Не публиковать их, кадры, annotations и официальные test-данные.
- Рабочий каталог находится внутри OneDrive: перенесите data/models/artifacts/runtime вне синхронизации или отключите синхронизацию этих каталогов. Локальный inference не управляет OneDrive и резервными копиями ОС.
- Uploaded MOV получает UUID-имя в системном TEMP (либо FORTEVISION_UPLOAD_DIR), удаляется после обработки/ошибки. После аварии возможны остатки; в Docker uploads находятся в tmpfs.
- JSON результата с evidence хранится в SQLite по FORTEVISION_JOB_DB (по умолчанию рядом с uploads, вне проекта). TTL — верхняя граница хранения, по умолчанию час. При достижении max_jobs удаляется самый старый завершённый результат; активные задания не вытесняются. После рестарта незавершённые jobs получают failed; завершённые сохраняются до TTL/удаления.
- Удаление завершённого результата: кнопка UI или авторизованный DELETE /api/v1/jobs/{id}. SQLite secure_delete включён; это не обещание уничтожения копий на SSD, в snapshots или резервных копиях.
- UI хранит файл в памяти сессии и может держать загруженные кадры в браузере. Для полного завершения демонстрации закройте вкладку/сессию. Экспортированные пользователем JSON и изображения автоматически удалить невозможно.
- Логи сервиса не должны содержать API-ключ, видео или base64. Внешние ссылки нормативного справочника открываются пользователем; inference их не запрашивает.

## Очистка после остановки API

```powershell
python -m scripts.cleanup_runtime
python -m scripts.cleanup_runtime --apply --purge-results
```

Первый вызов только показывает количество кандидатов. Второй удаляет generated UUID uploads/results и результаты SQLite; модель и исходный data-каталог не трогает. OS-lock блокирует очистку при работающем новом API. После старого сервиса без lock оператор также обязан убедиться, что он остановлен. Выбор файлов ограничен служебными UUID-именами внутри настроенного upload_dir, симлинки не удаляются.

После дататона отдельно удалить исходные data, contact sheets, локальные QA-скриншоты с кадрами и отчёты artifacts, скачанные JSON, копии в корзине/backup/OneDrive в соответствии с условиями организатора. Эта команда намеренно не удаляет их автоматически. При работе в Docker `job_state` также содержит результаты и требует очистки по окончании разрешённого срока.
