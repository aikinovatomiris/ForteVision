## Review routing — no unsupported automatic findings

A fixed alert threshold of 0.80 was evaluated against the previous 0.55 on the same grouped 32-video protocol. Binary false alarms fell from 11/16 normal videos to 2/16, but only 2/16 positive videos generated alerts and none had the correct type. A sensitive threshold 0.35 did not improve video-level candidate recall: 10/16 positives found, 6 missed. This threshold-only detector was NOT deployed as an accuracy improvement.

Active response now routes all existing classifier hypotheses to `review_candidates`, retaining their original timestamp, context, JPEG evidence, candidate type and normative-context reference. No category currently has adequate independent correct-type validation, so automatic `violations` are empty for this classifier. This is ABSTENTION, not zero-error recognition. The model still misses events; the routing change does not fix that. No confidence threshold was raised in candidate generation, and no earlier candidate interval was deleted. Priority is high at score >=0.80; this is an uncalibrated score, not correctness probability.

UI displays `needs_review` and the hypothesis cards instead of a clean verdict. API preserves its historical binary verdict field for compatibility; consumers MUST use `assessment_status`, `review_required`, `review_candidates`, and `analysis_complete`. In this mode `verdict=no_violation` means no automatic finding, NOT that the video is normal. Consumers/jury scripts reading only the old field cannot assess this review mode as a successful automatic detector. Model/backend is still incomplete for submission as an autonomous violation detector.

78 tests pass. `artifacts/triage_evaluation.json` contains threshold evaluation; `artifacts/review_api_regression.json` records live X16/X17/X25 checks. Backups under `artifacts/triage_backup` allow restoring the previous interface semantics.

Actual recognition work still required: resolve contradictory category descriptions, annotate visible document/receipt/cash distinctions and safe/door states at higher detail, and obtain multiple independent positive/negative examples per rule. Existing sparse boxes contain storage, laptop and cash-counter categories, not identity documents or tiny keys. A classifier trained only on these boxes cannot verify document identity or locking actions. Evaluate exact event type and temporal localization by whole-video groups, not just whether any alert appears anywhere in a positive video.
