# Граница работ backend / ML

Код `ml/`, weights, classifier и обучающая разметка не меняются доработками сервиса. ML-разработчик владеет точностью, типами, локализацией, наблюдаемыми описаниями, sampling/threshold и validation. Backend владеет доставкой, deadline, схемой, JPEG-валидацией, хранением и представлением.

## Совместимый результат

Точка интеграции остаётся `python -m ml.predict --video PATH --model PATH --weights PATH --device cpu --budget SECONDS --output PATH`. Никаких сетевых скачиваний при inference. Ненулевой exit code → failed. API ограничивает процесс оставшимся общим временем. Поддерживайте числовой float-бюджет, включая значения меньше секунды.

JSON должен содержать `verdict` и `violations`. Каждое событие: type, timecode_sec, description, evidence_frames. `image_base64` должен декодироваться в настоящий JPEG, 1–3 кадра, не более 4096 px на сторону. Общий output ограничен 16 MiB. Лишние обязательные поля не вводить. API добавляет job_id/status и измеренное время. Не возвращайте job_id/status из ML CLI.

Для обученных типов добавьте необязательный стабильный `event_type` (например, ID категории из согласованной taxonomy). `type` — человекочитаемое имя. `description` — только действительно наблюдаемое действие и ограничения вывода; нельзя превращать общий score в выдуманный сюжет. Не переносите описание research в prediction без детектора соответствующего действия.

## Проверенные нормативные ссылки

Backend не сопоставляет бинарный score с нормой. Адаптер `app/rule_links.py` принимает event_type только для конкретного типа (не общей категории), ищет записи в `configs/rules.json` и проверяет:

1. Поля источника, пункта, проверяющего и даты, требуемые RuleEngine.
2. `detector_model_sha256` точно совпадает с текущим classifier.joblib.
3. `validation_report` указывает на существующий локальный отчёт (относительный путь считается от configs).
4. Ссылка использует HTTPS и официальный домен adilet.zan.kz / old.adilet.zan.kz / nationalbank.kz / www.nationalbank.kz.

Полная запись содержит `event_type`, `source_title`, `source_url`, `section`, `verified_by`, `verified_at`, `detector_model_sha256`, `validation_report`. Отчёт должен включать сопоставление наблюдаемых условий/исключений с классом и результаты проверки. Существование файла и хеш — технический допуск; они не заменяют содержательную экспертизу и не доказывают юридическую корректность.

При совпадении backend добавляет optional `rule_references` и источник в description; UI показывает документ, пункт и ссылку. Переданные самим ML rule_references не считаются автоматически проверенными и удаляются до этого сопоставления. Пустой каталог остаётся допустимым технически, но требование ТЗ о нормативе для события остаётся незакрытым до подтверждения типов и правил.

Не копируйте весь research/rules.json в configs: это разные схемы и разные статусы готовности. Привязки для текущего бинарного baseline намеренно отсутствуют. После замены модели старые привязки перестают применяться, пока не проверен новый хеш.

## Передача нового релиза

Передайте комплект модели + metadata + weights, перечень типов, новые честные метрики, утверждённые привязки и лицензионные сведения. Заменять комплект следует при остановленном сервисе; UI/API затем перезапустить. Не менять JSON-хеш вручную для обхода проверки. Backend не запускает train и не подбирает threshold.
